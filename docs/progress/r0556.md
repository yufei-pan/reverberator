Note for that round's design: the entry on the top folder's record plans "the mount points in an attribute of their own";
on ext4 and f2fs every extended attribute of a folder shares one block of about 4 KiB (xattr(7)), and about 100 mount points
would not fit alone either, so the design picks where the set is kept.

## Calls to confirm

- The final review's Important finding (an entry already past 4,095 bytes inside a version) is deferred, not asked: a
  deferral needs no ask, the fix is not small, and no live job is near the limit. D4's known limitation now names it.
- The pause rule for an inner disk on a pool (it can lose a disk's files past Keep N) is deferred, not a known limitation:
  a data loss is always worth fixing; no live job has a pool inner disk.
- Not an issue, with reasons in the round's triage: a folder above the walk swapped for a link after the walk or the event
  read it is followed by the path-based reads (the spec's ruling; the final review found the round narrows it, the walk's
  own open taking no link). What remains: a local user who can write in a monitored tree and win a race can get files the
  daemon reads by path into a version, with their own owners and modes. A fix would be every consumer reading by handle (a
  candidate, not agreed).
- Behaviour changes beyond the spec: a file swapped for a link after the check's look counts as a change; the UNREADABLE
  line names a place that cannot be looked at, with its error ("left out of this version; the version before cannot be
  looked at (<error>)"); a restore's check names an unmounted branch by its branch, and looks at a branch the user could
  not open; the size estimate charges a batch folder only where a folder still is (or a link to one); history no longer
  raises the open-file limit; an attribute change synced in place is measured by its own path.
- The record of the top folder: a failed write keeps the older record, not none (removing it would leave no inner disk
  paused over a lost database).
- A refused folder attribute change (a link or a file put by hand at a folder's place in a version) is found again at each
  full comparison until another batch moves the matched time on: 0.55.5's behaviour.
- The test VM gate's expected skips: tests that need a user other than root (they pass in the container), and the inotify
  queue-overflow test, whose name says it skips when the queue cannot be filled (it passes in the container).
- One test assumes the monitored root has no extended attributes (true on the test hosts; a host that labels folders with
  security.selinux would fail it).
- The test oracle reads a version's links with no guard (tests/vault_oracle.py, entry_view() and daemon_links()): a
  power-loss run on f2fs that leaves a version's link with no text (README's known limitation) would stop the oracle with
  an error instead of a verdict. The round's crash and power-loss runs passed; if one fails that way, the fix is in the
  oracle, as this round made for staging links (kept_staging_link()).
- The shared lessons file's lines for this round are committed in that repo and not pushed: the push was refused by the
